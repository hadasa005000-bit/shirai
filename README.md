# היכל הניגון — אתר שירים חסידיים/חרדיים

אתר קטלוג שירים עם:
- מיון שירים לפי **קטגוריות/נושאים** (שבת, שמחה, התעוררות וכו')
- **צפייה בקליפ** (הטמעת יוטיוב) + **קישור הורדה לדרייב**
- **"X מחוברים כעת"** בזמן אמת (דרך Redis)
- **הרשמה/כניסה** למשתמשים
- **דשבורד ניהול** (`/admin`): שירים, קטגוריות, משתמשים, ובוט
- **בוט** שסורק ערוצי יוטיוב / מונחי חיפוש ומוצא שירים חדשים אוטומטית —
  כל שיר שהבוט מוצא נכנס כ"ממתין לאישור" ולא מוצג באתר עד שמנהל מאשר אותו.
  הבוט **לא מוריד ולא מארח קבצי שמע** — הוא רק מקשר לסרטון ביוטיוב. קישורי
  ההורדה (Drive) תמיד מתווספים ידנית ע"י מנהל, כדי לוודא שיש זכות חוקית
  להפצת הקובץ.

## טכנולוגיה
Next.js 14 (App Router) + TypeScript + Tailwind, Prisma + PostgreSQL,
NextAuth (התחברות), Redis (ioredis) למחוברים כעת.

---

## שלב 1: הרצה מקומית (לבדיקה לפני העלאה)

```bash
npm install
cp .env.example .env      # ומלאו את הערכים (לפחות DATABASE_URL)
npm run db:push           # יוצר את הטבלאות במסד הנתונים
npm run db:seed           # יוצר משתמש מנהל ראשוני + קטגוריות לדוגמה
npm run dev
```

האתר יעלה בכתובת http://localhost:3000, וניהול בכתובת http://localhost:3000/admin
(התחברו עם הפרטים שהגדרתם ב-SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD).

```bash

   ```

## שלב 3: יצירת Redis ב-Aiven (עבור "מחוברים כעת")

1. הרשמו/התחברו ב-aiven.io.
2. **Create service** → בחרו **Redis** (או Valkey, זהה מבחינת ה-API) → תוכנית
   החינמית (Free/Hobbyist) מספיקה לגמרי לצורך הזה → בחרו אזור קרוב.
3. אחרי כמה דקות השירות יעלה. בדף השירות, תחת **Connection Information**,
   העתיקו את ה-**Service URI** — זה בדיוק הערך של `REDIS_URL`
   (הוא כבר יתחיל ב-`rediss://` עם TLS).

## שלב 4: פריסה ל-Render

⚠️ **חשוב אם משתמשים בתוכנית החינמית (Free)**: לתוכנית החינמית אין גישת
Shell/SSH, אז אי אפשר להריץ `npm run db:push` / `npm run db:seed` בצורה
הרגילה. הפרויקט בנוי כך שזה עדיין עובד בלי טרמינל בכלל:

- **יצירת הטבלאות** קורית אוטומטית בכל דיפלוי, כי ה-Build Command כולל
  `npx prisma db push` (ראו למטה).
- **יצירת משתמש מנהל ראשוני** קורית דרך כתובת אחת בדפדפן:
  אחרי הדיפלוי הראשון, הוסיפו משתנה סביבה `SETUP_SECRET` עם ערך אקראי
  משלכם (לדוגמה `my-setup-key-8f3a`), ואז גשו פעם אחת לכתובת:
  ```
  https://הכתובת-שלכם.onrender.com/api/setup?key=my-setup-key-8f3a
  ```
  זה ייצור את הקטגוריות ואת משתמש המנהל (עם הפרטים מ-`SEED_ADMIN_EMAIL`
  / `SEED_ADMIN_PASSWORD` שהגדרתם, או ברירת המחדל אם לא הגדרתם). הנתיב
  מסרב לפעול פעם שנייה אחרי שכבר קיים מנהל, כך שאין סכנה שמישהו יריץ
  אותו שוב בטעות.

### אפשרות א' — עם render.yaml (הכי מהיר, מומלץ)
בפרויקט כבר קיים קובץ `render.yaml` שמגדיר בבת אחת: שרת האתר, מסד
PostgreSQL, ו-Cron Job להרצת הבוט פעם ביום.

1. היכנסו ל-dashboard.render.com → **New** → **Blueprint**.
2. חברו את חשבון ה-GitHub שלכם ובחרו את הריפו `heichal-hanigun`.
3. Render יזהה את `render.yaml` ויציע ליצור את כל השירותים ביחד — אשרו.
4. אחרי היצירה, היכנסו לשירות `heichal-hanigun` (השרת) → **Environment**
   והוסיפו את המשתנים שמסומנים "sync: false" בקובץ:
   - `NEXTAUTH_URL` — הכתובת הסופית של האתר (לדוגמה `https://heichal-hanigun.onrender.com`, או הדומיין שלכם)
   - `REDIS_URL` — מה-Service URI שהעתקתם מ-Aiven בשלב הקודם
   - `YOUTUBE_API_KEY` — ראו שלב 5 למטה
5. אותם `REDIS_URL` ו-`YOUTUBE_API_KEY` צריך להוסיף גם לשירות ה-Cron
   `heichal-hanigun-bot` (רק YOUTUBE_API_KEY שם, כי הבוט לא צריך Redis).
6. אחרי הפריסה הראשונה, פתחו **Shell** בשירות הראשי והריצו פעם אחת:
   ```bash
   npm run db:push
   npm run db:seed
   ```
   זה יוצר את הטבלאות ואת משתמש המנהל הראשוני.

### אפשרות ב' — יצירה ידנית (מה שרואים עכשיו במסך של Render)
אם אתם ממלאים טופס "New Web Service" ידנית (לא Blueprint), אלו הערכים
הנכונים:

| שדה | ערך |
|---|---|
| Language | **Node** (לא Ruby — זו ברירת המחדל השגויה שמוצגת) |
| Build Command | `npm install && npx prisma db push && npm run build` |
| Start Command | `npm run start` |
| Instance Type | Free מספיק להתחלה |

לפני שלוחצים "Deploy" — צרו קודם מסד נתונים: **Dashboard → New →
PostgreSQL**, תוכנית Free, ואז העתיקו את ה-**Internal Database URL** שלו
לתוך משתנה הסביבה `DATABASE_URL` בטופס של השירות.

**משתני סביבה שצריך למלא בטופס** (Environment Variables):
- `DATABASE_URL` — מהמסד שיצרתם
- `NEXTAUTH_SECRET` — כל מחרוזת אקראית ארוכה (20+ תווים)
- `NEXTAUTH_URL` — את הכתובת הסופית של האתר תדעו רק אחרי הדיפלוי
  הראשון (`https://שם-השירות.onrender.com`) — אפשר למלא בהתחלה כל ערך
  זמני ואז לחזור ולעדכן אחרי שרואים את הכתובת האמיתית
- `SETUP_SECRET` — מחרוזת אקראית משלכם, לשימוש חד-פעמי (ראו למעלה)
- `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` — פרטי הכניסה הרצויים למנהל
- `REDIS_URL` — מ-Aiven (אופציונלי בהתחלה, אפשר להוסיף מאוחר יותר)
- `YOUTUBE_API_KEY` — למען הבוט (אופציונלי בהתחלה)

אחרי שהאתר עולה בהצלחה, גשו פעם אחת ל-
`https://הכתובת-שלכם.onrender.com/api/setup?key=הערך-שנתתם-ל-SETUP_SECRET`
כדי ליצור את משתמש המנהל, ואז תוכלו להתחבר ב-`/login`.

### חיבור דומיין משלכם
בדף השירות → **Settings** → **Custom Domains** → הוסיפו את הדומיין שלכם
ועקבו אחרי הוראות ה-DNS (בדרך כלל רשומת CNAME אל כתובת ה-Render שלכם).

## שלב 5: מפתח YouTube API (עבור הבוט)

1. היכנסו ל-console.cloud.google.com וצרו פרויקט חדש (או השתמשו בקיים).
2. **APIs & Services** → **Library** → חפשו **YouTube Data API v3** → **Enable**.
3. **APIs & Services** → **Credentials** → **Create Credentials** → **API key**.
4. את המפתח הזה שימו בערך `YOUTUBE_API_KEY`.

שימו לב: ל-YouTube Data API יש מכסת שימוש יומית חינמית (בדרך כלל 10,000
"יחידות" ליום — כל בקשת חיפוש עולה כ-100 יחידות, כך שיש מקום לכ-100
סריקות ביום, מעל ומעבר למה שצריך להרצה יומית).

## איך משתמשים בבוט

1. היכנסו ל-`/admin/bot`.
2. הוסיפו מקור: או **ערוץ יוטיוב** (מזהה הערוץ, מתחיל ב-`UC...` — אפשר
   למצוא אותו בעמוד "אודות" של הערוץ ביוטיוב), או **חיפוש חופשי**
   (מילות מפתח, למשל "שיר חדש חסידי 2026").
3. לחצו **הרצה עכשיו** לבדיקה מיידית, או פשוט תנו ל-Cron Job ב-Render
   להריץ את זה אוטומטית (ברירת המחדל: כל יום ב-06:00 UTC — אפשר לשנות
   בקובץ `render.yaml`, שדה `schedule`, בפורמט cron רגיל).
4. שירים חדשים שנמצאים מופיעים בדף **שירים** תחת הסינון "ממתין לאישור".
   בדקו כל שיר, ואם רלוונטי — לחצו **פרסום** (ואפשר גם להוסיף קישור
   הורדה מהדרייב באותו שלב, דרך עריכת השיר).

## הערה לגבי זכויות יוצרים

שימו לב: קישורי ה"הורדה" באתר אמורים להוביל לקבצים שיש לכם זכות חוקית
להפיץ אותם (למשל שירים שהעליתם בעצמכם לדרייב שלכם, בהסכמת האמן/חברת
התקליטים, או תוכן ברישיון פתוח). מומלץ להימנע מהעלאת קבצי הורדה של
שירים ללא רשות בעל הזכויות. הצפייה בקליפ מוטמעת ישירות מיוטיוב ולכן
אינה מהווה אחסון של הקובץ באתר עצמו.
